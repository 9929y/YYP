# Extending the site

## Folders

```
src/
  components/
    ui/          shadcn primitives (generated by `npx shadcn add ...`)
    islands/     React components used from .astro files with a client directive
    *.astro      zero-JS building blocks (sections, cards, media)
  layouts/       BaseLayout.astro (html/head/nav/footer)
  pages/         routes
  content/       words + media references (see README)
  content.config.ts
  lib/utils.ts   cn()
  styles/global.css   Tailwind entry + design tokens
public/assets/   images, videos, lottie, fonts (served as /assets/...)
```

## shadcn/ui primitives

`components.json` is already configured (style `new-york`, CSS variables, `@/` aliases).

```bash
npx shadcn@latest add button dialog
```

Files land in `src/components/ui/`. Use them from `.astro` files:

```astro
---
import { Button } from '@/components/ui/button';
---
<Button client:visible>Read the case</Button>
```

A shadcn component with no state (Button, Card, Badge) can be rendered without a
client directive: Astro then emits plain HTML and ships no JS for it.

## Pasting a 21st.dev component

1. Copy the `.tsx` into `src/components/islands/` (or `src/components/ui/` if it is a
   primitive).
2. Fix imports that assume Next.js:
   - `next/image` → `<img>` (or Astro's `<Image>` from the `.astro` side)
   - `next/link` → `<a>`
   - `next/font/*` → drop; fonts are set in `global.css`
   - `"use client"` → delete the line (harmless if left)
   - `framer-motion` → `motion/react` (already installed)
3. Mount it from an `.astro` file with the lightest directive that works:
   - `client:visible` for anything below the fold
   - `client:idle` for above-the-fold decoration
   - `client:load` only for things that must be interactive immediately
   - `client:media="(hover: hover)"` for hover-only effects
4. Run `npm run check`.

## React islands: the two rules

**Islands do not share React state.** Each `client:*` component is its own React
root. A theme toggle in the nav cannot use `useContext` to reach a card in the
body. Options, in order of preference:

- Put both pieces inside one island.
- Share through a nano store (`npm i nanostores @nanostores/react`).
- Share through the DOM (a `data-*` attribute on `<html>`, CSS variables).

**Astro components cannot be children of React components** in a way that
re-renders. Passing `<slot />` content into an island works for static HTML, not
for children that the React component needs to control.

## Adding a case study

1. Create `src/content/cases/<slug>.md` with the frontmatter fields in
   `src/content.config.ts` (`slug` must equal the filename).
2. Put media under `public/assets/images/<slug>/` and reference it as `/assets/...`.
3. Add the slug to `caseOrder` in `src/content/site/navigation.json` so prev/next work.
4. `npm test` checks references and required fields; `/work/<slug>` renders automatically.

## Motion

Use `motion/react` inside islands (see `Reveal.tsx`). Always respect
`useReducedMotion()`. Prefer `whileInView` with `once: true` for entrance effects.

## Do not

- Re-introduce the Webflow runtime, jQuery, or the old `yy-*` scripts.
- Reference `-p-NNN` image variants; let Astro generate sizes if needed.
- Put copy in components. Words go in `src/content/`.
